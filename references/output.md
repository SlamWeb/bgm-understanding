# 默认摘要与按需明细

默认 `bgm-understanding.json` 是 `bgm-editing-brief-v2`，包含剪辑决策需要的数据：

- `overview`：BPM、典型小节长度、主要音色、人声/语言和情绪候选。
- `timeline`：合并连续同类段落，给起止秒数、相对能量/走势、声音密度及音色/人声/情绪候选。
- `change_candidates`：少量值得考虑的变化时刻，不是必须切的点。
- `sound_motion`：`columns` 定义紧凑数值行：开始、结束、相对能量、低/中/高频功率占比、每秒起音数；最多48窗、覆盖全长。用它看渐强、变密、低频进入或音色变亮；时间窗是汇总，不用于逐次敲击定位。
- `cut_points`：全部 `beats` 和 `bar_starts` 秒数，以及起音 `[秒,相对强度]` 数组 `onsets`；并非只给BPM。`onset_coverage=full_detected_events` 表示包含完整检测结果，`summary_only` 明确是原始事件文件缺失时的有限摘要。节拍格不等于具体乐器敲击，起音未识别具体声源。
- `text_status` / `text_cues`：默认 `skipped_not_requested` / `[]`，表示未请求文字识别，不能解释为纯音乐。用户显式开启转写时提供带来源的句段候选。
- `detail_ref`：诊断和更多证据的详细文件及SHA256。卡点时间已在主文件内；筛选区间可用 `extract_bgm_events.py --detail <主JSON> --start 30 --end 45`，不必另写分析脚本或读取诊断。

交付文件在信息层次上聚合重复测量，保留直接影响剪辑的全部时间点，不追求固定行数。时间线/文本每项一行，时间数组紧凑保存。只有详细文件时用 `summarize_bgm.py --analysis <详细JSON> --output <新主JSON>` 导出，不需要重跑模型。v1旧简版没有完整卡点，不再作为默认交付。时间单位为秒，能量/密度不是情绪/BPM。

主输出编译器有可执行检查：仅允许剪辑接口字段、最多96段时间线/24个变化候选/48个走势窗口，除完整卡点和可选文本外描述开销不超过28KB。超过预算报错，保留原始证据供修正，不静默截断卡点。检查的是结构和实际字节，不靠把几千行压成一行蒙混过关。长曲的完整拍点数组仍会占空间；按选段读取可减少上下文。`output-quality.json` 记录实际字节、行数和事件数量；不把机械检查当听感评分。

## 详细分析（按需）

详细文件为 `bgm-analysis-detail.json`，schema 为 `bgm-understanding-v2`。v1 四部分继续保留，新增声音语义和文字层。旧版已交付的大型 JSON 同样可作为详细输入。以下字段不属于默认摘要；先选区间再读取所需部分。

| 字段 | 下游用途与边界 |
|---|---|
| `status` / `analysis_status` | complete代表请求的核心、语义等阶段完成；默认转写单独标为 skipped_not_requested，不算失败。不代表听感准确。partial明确请求但缺失的模块。 |
| `audio` | 解码 WAV、原始音频、SHA256、时长与原文件起始偏移；所有秒数从 WAV 开头算。 |
| `rhythm` | BPM 候选、拍点、小节起拍和其他 BPM 候选。拍不等于乐器攻击，半速/倍速分歧不等于音频加速。 |
| `sound_events` | 相对突出的起音及本曲内强度；最多32条，完整事件引用在 all_events_file。没有声源身份。 |
| `dynamics` | 原始每0.5秒跨声道 RMS，最终最多48个按时长加权汇总窗口；含、相对能量、低中高频能量、检出密度与前后变化；最后不足一窗仍覆盖。静音 dBFS为null。 |
| `structure` | 段落、名称、变化边界候选及模型/信号回退来源。即使两边名称相同，边界也可能有用。开头结尾极短的记账段不作有意义边界。 |
| `entry_candidates` | 合并邻近变化证据，优先保留结构边界，给出附近小节起拍供对齐；按支持来源数量排序，不是校准置信度或最爽时刻。 |
| `instruments` | YAMNet 模型预测的具体乐器候选，含全曲摘要与时间窗口；音色相近、混音遮蔽会误判。窗口分类不能归因每个起音。 |
| `vocals` | 显式说话/歌唱类别的分数时间线和活动区间，保留阈值、上下文长度；低分可以是不确定而非绝对无人声。 |
| `lyrics` | 自动识别的歌词或说话内容，segments 含 start/end/text/type、词数量和质量提示；时间相对同一个 canonical WAV。未获支持时空列表。完整词时轴、转写与拒收候选在 raw_report_file，避免为普通素材编排塞入逐字诊断。 |
| `emotion` | 真实音乐标签模型预测 happy/sad/relaxed/aggressive 的独立分数与时间窗；不是用能量阈值生成的情绪，也非互斥概率。人声朗读等域外音频保留 applicability 提示。 |
| `editing_use` | 剪辑使用说明；素材、转场和节奏由选题决定。 |
| `uncertainty` / `raw_files` / `semantic_models` | 人工复核状态、模型候选边界、完整报告和模型权重身份；未人工听证不写成真值。 |

连续没有已接受起音但仍有能量时，possible_onset_detection_gaps提醒可能漏检，不能解释为无声音或无节奏。多声部混音和短片段都可能让模型漏检或错判。能量、起音数量、BPM和段落语义是不同量。

原始All-In-One末端可能超出真实时长几帧，最终事件会剔除尾部超界点，段落终点限于真实时长；明显超界或不同音源报告会报错。人工标记是可选的创作偏好，另存而不冒充自动结果。

`lyrics.segments` 是 ASR 句/短语候选，不是精确诗句、歌词或音节边界。唱词拖音、变速、古文同音字和伴奏残留会导致错误；模型诊断分数不是文字正确率。文字与音乐情绪有不同来源，不能由一个标签推出整首叙事。
